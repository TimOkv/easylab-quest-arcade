## Что должно заработать

Ни один статус отправки не зависает навсегда, ошибки-баги не выдаются за «нет интернета», безнадёжные отказы сервера не долбят его вечно, звук не будит AudioContext без жеста, кнопки на экране аркады не теряют быстрый тап. Плюс одна версия DOM-хелперов и UUID на весь проект вместо копий в каждом экране.

## Находки ревью, которые закрывает таск

1. `src/leaderboard/screen.ts:340` — при сбое `flush` после смены ника карточка зависает на «Отправляем…».
2. `src/app/app.ts:165` — любая ошибка `submitRun` (включая баг) показывается как «ждёт интернета» без лога.
3. `src/services/curator.ts:90` — неустранимые отказы `BAD_NAME`/`BAD_COINS` повторяются бесконечно.
4. `src/app/app.ts:62` — `questCompletedPayload` на незавершённом состоянии может выдать пустой код и выдуманную дату.
5. `src/services/sfx.ts:97` — `play()` создаёт AudioContext до жеста; `src/app/app.ts:252` — `destroy` будит AudioContext через `unlock()`.
6. `src/arcade/arcade.css:8` — `touch-action: none` на всей области аркады, кнопки тоже `none`.
7. Четыре копии DOM-хелперов `el`/`button` (quest: `screen.ts:33` и `puzzle-ui.ts:11`, arcade, verify `dom.ts`, возможно leaderboard) и три реализации UUID v4 (`core/state`, `services/leaderboard.ts:78`, `arcade/game.ts:66`).
8. Слепая приёмка: сетевой сервис Supabase собирается в чанк `dist/assets/rest-*.js` весом 4.26 КБ минифицированным (2.53 КБ gzip) — бриф требует «< 3 КБ кода».
9. `src/app/app.ts:204,61` — литералы `16` и `75` вместо `PLAYER_NAME_MAX`/`MAX_TOTAL_COINS`.

## Критерии приёмки

- [ ] Смена ника в рейтинге при упавшей отправке: карточка выходит из «Отправляем…» в видимое состояние ожидания/ошибки с возможностью повторить; юнит-тест с отказывающим сервисом.
- [ ] `submitRun`: `NetworkError` → «ждёт интернета» (как сейчас); любая другая ошибка → `console.error` и отличимый от офлайна текст; тест на оба случая.
- [ ] Отказы сервера `BAD_NAME`/`BAD_COINS` при регистрации квеста больше не повторяются в цикле (тест: после такого отказа за время ≥ 3 интервалов повтора — ровно один вызов RPC); монеты и код игрока при этом не теряются локально.
- [ ] `questCompletedPayload` для незавершённого квеста или квеста без кода возвращает `null`, и мост ничего не отправляет; тест.
- [ ] AudioContext создаётся только внутри `unlock()`, вызванного жестом; `play()` до разблокировки — тихий no-op; `destroy` приложения не создаёт и не будит контекст; тесты.
- [ ] На экране аркады `touch-action: none` — только у `canvas` (и зон тач-управления, если это отдельные элементы); у кнопок — `manipulation`. Проверка вычисленным стилем в существующем e2e или юнит-тест на CSS.
- [ ] Один модуль DOM-хелперов (например `src/core/dom.ts` — выбери по месту), все экраны используют его; копий `el`/`button` в экранах нет. Одна реализация UUID v4 — та, что в `core/state` (или вынесенная рядом), остальные её импортируют. Поведение и тексты экранов не меняются.
- [ ] Сетевой REST-клиент Supabase (`src/services/rest.ts` — то, что делает fetch к `/rest/v1/*`) после сборки весит < 3 КБ минифицированным, без gzip; `npm run check:size` проверяет это отдельной строкой и падает при превышении. Функциональность и коды ошибок клиента не меняются.
- [ ] Литералы `16`/`75` в `app.ts` заменены константами из `core/rules`.
- [ ] `npm run build`, `npm run check:size`, `npm test` и `npx playwright test` зелёные; число юнит-тестов выросло.
