## Что должно заработать

Код `EZ-XXXX` — единственное доказательство прохождения: ребёнок присылает его куратору, куратор начисляет монеты по коду. Поэтому через публичный anon-ключ нельзя перебором выяснить, какие коды существуют, и нельзя ничего сделать со старой таблицей рейтинга.

## Критерии приёмки

- [ ] После применения `schema.sql` на базе, где уже была старая таблица `leaderboard` (из §4.2 брифа), у `anon` и `authenticated` нет никаких прав на `leaderboard_legacy_v0`, и на ней включён RLS; тест на PGlite это доказывает (попытка select/insert от роли anon — ошибка прав).
- [ ] Anon-RPC, по ответу которых можно отличить существующий код от несуществующего, ограничены по частоте: больше N (выбери разумное N, например 30) «промахов» по несуществующим кодам с одного источника за час → `RATE_LIMIT`, пока окно не истечёт. Источник — адрес клиента из заголовков запроса PostgREST (`current_setting('request.headers', true)` → `x-forwarded-for`, первый адрес), при отсутствии заголовка — общий пул. Честный клиент со своим кодом в лимит не упирается (проверки своего кода не считаются промахами). Тест на PGlite: N+1 промахов подряд → `RATE_LIMIT`; свой код после этого по-прежнему работает, если лимит считается только по промахам — или явно зафиксируй в CONCERNS, почему нет.
- [ ] `ezq_fail` — `volatile`; все существующие SQL-тесты зелёные.
- [ ] Повтор `submit_arcade_score` с уже известным `p_run_id`, но другим `p_code`, не возвращает данные чужого забега (ошибка или новый отказ); тест.
- [ ] Коды ошибок RPC остаются из существующего набора (`NO_QUEST BAD_CODE BAD_NAME BAD_COINS CHEAT_SPEED TOO_SHORT SCORE_RANGE RATE_LIMIT CODE_TAKEN FORBIDDEN BAD_LIMIT`) — клиент в `src/` не меняется. Если без нового кода не обойтись — `BLOCKED` с объяснением.
- [ ] `schema.sql` остаётся идемпотентным: повторное применение на уже установленной базе проходит (тест есть — не сломать).
- [ ] `npm test` зелёный, число тестов выросло.
