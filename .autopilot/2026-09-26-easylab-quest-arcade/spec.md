# Спецификация: EasyLab Quest & Endless Arcade

Источники: `2026-09-26-brief.md` (сообщение пользователя + снимок CLAUDE.md + Дополнения брифинга), `reference.md`.
Глубина: deep. Режим: interview.

## Задача

Школа Easycode хочет, чтобы ученик 6–17 лет (ядро — 12) прошёл короткое сюжетное обучение основам программирования, получил за него честно заработанные EasyCoins, а куратор без ручной переписки мог проверить, сколько именно монет начислить. После квеста ученику нужна причина возвращаться каждый день — аркада с сезонным рейтингом школы и реальными призами за ТОП-3. Модуль должен жить внутри платформы EasyLab (iframe) и сам по себе.

## Решение

- **Квест**: 4 комнаты-зоны уютной пиксельной комнаты (картинка-референс), в каждой ровно одна загадка (переменные → if/else → циклы → функции). Монеты — по формуле попыток, подсказки помогают. Финал — экран триумфа с личным кодом `EZ-XXXX`, копированием и приглашением в аркаду. Квест одноразовый.
- **Аркада**: вертикальный пиксельный джампер с котиком в худи, 60 FPS, пружины, ракета, метка рекорда.
- **Рейтинг**: сумма очков всех забегов за сезон (с дневным лимитом), ТОП-10 с призовыми бейджами ТОП-3, своя позиция и отставание до ТОП-10, обратный отсчёт до итогов.
- **Куратор**: Google-таблица, заполняемая автоматически, и секретная страница `verify.html` — поиск по коду, «начислено», последние 50 завершений, управление сезоном, лимитом и модерацией ников.
- **EasyLab Bridge**: postMessage-протокол с платформой и стенд `parent_test.html`.

## Решения по реализации

### §1. Стек и сборка

- Vite + TypeScript (`strict`), без рантайм-зависимостей. Dev-зависимости: `vite`, `typescript`, `vitest`, `happy-dom` (тесты DOM-модулей), `@electric-sql/pglite` (тесты SQL — Postgres в WASM, потому что локального Postgres нет), `playwright` (дымовые e2e и скриншоты — браузеры уже в кэше машины). Почему: всё это только для разработки, в бандл не попадает.
- Мультистраничная сборка Vite: `index.html` (модуль), `verify.html` (куратор), `parent_test.html` (стенд). `base: './'`.
- Картинка-референс импортируется из `src/` модулем (`import roomUrl from './assets/room.jpg'`) — Vite даёт хэшированный относительный путь, битых путей не бывает. Больше файлов изображений нет: спрайты аркады, монетка HUD, робот, декоративные текстуры — код (canvas / CSS / inline SVG).
- Шрифт: `"TT Norms", "TT Norms Pro", system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` — TT Norms коммерческий, в бандл не кладём; для чисел HUD — моноширинный стек. Цвета бренда (брендбук §3.1): синий `#0068FF` (доминирует: основные кнопки, ссылки, акценты), голубой `#9BC4FF`, белый `#FFFFFF`; дополнительные (сняты с превью страницы брендбука, HEX там не подписаны — приблизительно): серый `#8E8A94`, чёрный `#1B1B1B`, лиловый `#B8A4FC`, бледно-голубой `#CAD6FF`, циан `#54C8F4`, ярко-голубой `#00B8FF`, маджента `#E500E6`, красный `#FF1F4B` (ошибки). Знак «загрузки» (штрихи по кругу) — индикатор загрузки. Дерево/тёмно-синий — из референса (рамки кнопок HUD как в референсе).
- Скрипты: `dev`, `build` (`tsc --noEmit && vite build`), `preview`, `test` (vitest), `test:e2e` (playwright), `check:size`, `check:css` (линтер префикса — тест vitest).

### §2. Модель состояния

`EasyQuestGameState` — ровно §4.1 CLAUDE.md, плюс аддитивные поля (§4.1 не меняется, только расширяется):

```ts
rooms[n]: { …как в §4.1; hintsUsed: 0 | 1 | 2 }
quest: { …; syncAttempts: number; lastSyncError: string | null }
arcade: { …; bestHeightPx: number; lastRun: { …; seed: number; countedScore: number | null } | null }
leaderboard: { …; seasonTotal: number; todayCounted: number; dailyLimit: number; isHidden: boolean;
               cachedTop: { rows: PublicRow[]; fetchedAt: number } | null }
meta: { …; theme: 'light' | 'dark' }
```

`playerName` — единственное имя ученика (`leaderboard.playerName`), им же подписывается запись куратора. Очередь забегов — отдельный ключ `ezq_pending_scores_v1` (массив `{ runId, payload, attempts, nextTryAt }`), чтобы запись сохранения и очереди не конкурировали.

### §3. Монеты (R16, R17, G07)

```ts
REWARDS = { 1: [10, 7, 5], 2: [15, 11, 8], 3: [20, 14, 10], 4: [30, 22, 15] }
reward(room, attemptsIncludingCorrect, hintsUsed) =
  hintsUsed >= 2 ? 0 : max(0, REWARDS[room][min(attempts, 3) - 1])
```
Подсказка 1: доступна при `wrongAttempts ≥ 1`. Подсказка 2: при `hintsUsed ≥ 1` (повторное нажатие на кнопку подсказки — буквально слова пользователя «если после 1 подсказки ребенок нажал еще раз на подсказку - монеты не даются»), с подтверждением. «Сейчас за верный ответ» в HUD = `reward(room, attempts+1, hintsUsed)`.

### §4. Загадки (G06 — один уровень, ~10–12 лет)

Общее для всех: взаимодействие «тап по карточке → тап по месту» (работает на тач, мыши и клавиатуре; перетаскивание pointer-событиями — бонусом, не обязательно); кнопка «Проверить» активна, когда ответ собран; объяснение ошибки зависит от конкретной ошибки; котик-рассказчик даёт вводную в 1–2 фразы.

1. **Переменные и типы** (комната 1, зона — ноутбук/монитор на столе). Три «коробки»-переменные: `имя: string`, `возраст: number`, `любитКодить: boolean`; четыре карточки-значения: `"Мурзик"`, `12`, `true`, `"12"` (ловушка: число в кавычках — строка). Верно: имя←`"Мурзик"`, возраст←`12`, любитКодить←`true`. Подсказка 1 — про кавычки у строк; подсказка 2 — прямо указывает, что `"12"` лишняя.
2. **IF / ELSE** (комната 2, зона — шкаф с роботом). Код: `if (signal === "red") { robot.stop() } else if (signal === "green") { robot.go() } else { robot.dance() }`. Датчик робота светится **жёлтым**. Вопрос: какая строка выполнится? Ученик тапает ветку. Верно — `else` (ловушка: ищут слово «yellow»). Подсказка 1 — «проверь по очереди каждое условие»; подсказка 2 — «ни red, ни green не подошли — куда попадает всё остальное?».
3. **Циклы** (комната 3, зона — книжный шкаф/стол с книгой). Задание: «Поставь на полку ровно 5 книг». Три слота кода; блоки: `for (let i = 0; i < 5; i++) {`, `for (let i = 0; i <= 5; i++) {` (6 книг), `for (let i = 1; i < 5; i++) {` (4 книги), `shelf.putBook()`, `shelf.takeBook()`, `}`. Верно: `i = 0; i < 5` → `putBook` → `}`. Превью показывает, сколько книг встанет при выбранном заголовке. Подсказки: считать повторения; прямо — «от 0 до 4 — это пять чисел».
4. **Функции и аргументы** (комната 4, зона — котик/главный экран). Показано объявление `function runMission(code) { if (code === "ARCADE") portal.open() }` и реплика котика «Запусти миссию с кодом ARCADE!». Ученик собирает вызов из токенов: `runMission`, `run_mission`, `(`, `)`, `"ARCADE"`, `ARCADE`, `=`. Верно ровно: `runMission ( "ARCADE" )`. Подсказки: имя функции и скобки; прямо — «строку пишем в кавычках».

Каждая загадка — объект с чистой функцией `check(answer) → { correct, mistake? }` (тестируется без DOM) и отдельным рендером.

### §5. Схема данных Supabase (R58 + G01/G02/G05/G04)

Изменения относительно §4.2 CLAUDE.md, продиктованные ответами пользователя:
- **`leaderboard` становится представлением** (публичное чтение ТОП-10 по `GET /rest/v1/leaderboard?order=score.desc,created_at.asc&limit=10` сохраняется буквально): строки текущего сезона без скрытых, колонки `player_name, score, created_at, runs_count` — без кодов и student_id. Данные — таблица `leaderboard_entries` (одна строка на `(season_id, verification_code)`, `score` = сумма засчитанных очков, без потолка 50000; `session_id` — последний, не UNIQUE; `is_hidden`). Причина: G01 (сумма забегов) несовместима с «одна строка = один забег, session_id UNIQUE, score ≤ 50000».
- **`arcade_runs`** — журнал забегов: `run_id uuid UNIQUE`, `verification_code FK`, `season_id FK`, `score 0..50000`, `counted_score`, `time_spent_seconds ≥ 5`, `jumps_count`, `day_msk date`, `created_at`. CHECK-и §4.2 переезжают сюда.
- **`seasons`**: `id, title, started_at, ends_at null, finished_at null, is_active` (частичный UNIQUE — ровно один активный). Сид: «Сезон 1».
- **`season_winners`**: `season_id, place 1..3, verification_code, player_name, score`.
- **`ezq_settings`** (одна строка): `daily_score_limit int default 3000`, `curator_secret_hash text`, `sheets_webhook_url text`, `sheets_webhook_secret text`.
- `quest_completions` — как в §4.2 + индекс по `student_id` и по `lower(player_name)`.
- RLS включён на всех таблицах; анонимной роли нет прямого доступа к таблицам. Анонимно доступны: `SELECT` представления `leaderboard` и RPC ниже.

RPC (все `SECURITY DEFINER`, `search_path` зафиксирован):

| Функция | Кто | Суть |
|---|---|---|
| `register_quest_completion(p_code, p_player_name, p_student_id, p_coins, p_completed_at)` | клиент | валидирует код/ник/0..75; если `p_student_id` уже есть → возвращает существующую запись с `restored=true`; конфликт кода → ошибка `CODE_TAKEN`; иначе вставляет и возвращает `{verification_code, coins_earned, completed_at, restored}` |
| `restore_by_student(p_student_id)` | клиент | `{verification_code, coins_earned, player_name, completed_at}` или null |
| `submit_arcade_score(p_run_id, p_code, p_session_id, p_student_id, p_player_name, p_score, p_time_spent, p_jumps)` | клиент | проверки 70–73; повтор `run_id` → идемпотентно; сезон закрыт по `ends_at` → `counted=0, season_closed=true`; `counted = min(score, limit − today)`; апсерт суммы; ответ `{counted, season_total, today_counted, daily_limit, rank, gap_to_top10, is_hidden, season_ends_at, season_closed}` |
| `get_my_standing(p_code)` | клиент | те же поля без записи — для экрана рейтинга |
| `get_season_info()` | клиент | `{title, ends_at, daily_limit, is_closed}` |
| `curator_*(p_secret, …)` | verify.html | `curator_check`, `curator_find(code)`, `curator_recent(limit ≤ 50)`, `curator_set_awarded(code, bool)`, `curator_leaderboard()`, `curator_set_hidden(code, bool)`, `curator_set_daily_limit(int)`, `curator_set_countdown(title, ends_at)`, `curator_finish_season(next_title)`, `curator_winners()`; секрет сверяется с `curator_secret_hash` (sha256 через pgcrypto `digest`); неверный → `FORBIDDEN` |
| `ezq_set_curator_secret(p_secret)` | админ в SQL-редакторе | не выдаётся роли anon |

Ошибки RPC — `RAISE EXCEPTION` с кодом в тексте (`NO_QUEST`, `BAD_CODE`, `BAD_NAME`, `CHEAT_SPEED`, `TOO_SHORT`, `SCORE_RANGE`, `RATE_LIMIT`, `CODE_TAKEN`, `FORBIDDEN`), клиент разбирает по префиксу.

Ранг: `rank() over (order by score desc, created_at asc)` среди нескрытых в сезоне; `gap_to_top10 = max(0, score_10го − мой + 1)` если я не в ТОП-10.

Google-таблица (R50): триггер `AFTER INSERT OR UPDATE OF is_awarded` на `quest_completions` → `net.http_post` на `sheets_webhook_url` с `{secret, event, row}`. Создаётся только если расширение `pg_net` доступно (`DO`-блок с проверкой) — в PGlite-тестах пропускается. Apps Script: `doPost` проверяет секрет из Script Properties, `insert` → строка, `awarded` → меняет «Статус» строки с этим кодом.

### §6. Сетевые сервисы клиента

- `rest` (< 3 КБ минифицированного кода, проверяется тестом по сборке модуля esbuild-ом Vite): `createRestClient({ url, anonKey, fetchImpl, timeoutMs = 8000 })` → `select(pathWithQuery)`, `rpc(name, args)`; заголовки `apikey`, `Authorization: Bearer`; ошибки: `NotConfiguredError`, `NetworkError` (включая таймаут), `RpcError(code, message)`.
- Отступление от буквы брифа: запись прохождения идёт не прямым `POST /rest/v1/quest_completions`, а через RPC `register_quest_completion` — иначе невозможно G03 (узнать ученика по ID без публичного чтения таблицы с именами детей) и защититься от подделки полей. Цель брифа (запись в реестр в момент финиша со всеми полями) сохранена.
- Конфигурация: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_BRIDGE_EXTRA_ORIGINS` (через запятую). Пусто → демо-режим (история 69).

### §7. Аркада — движок

- Холст 450×800 логических px. Константы (стартовые, подбираются в тикете с соблюдением истории 57): гравитация ≈ 2200 px/с², скорость прыжка ≈ 950 px/с (высота ≈ 205 px), пружина ×√2.5 по скорости, ракета 2 с × 900 px/с, горизонтальная скорость ≈ 380 px/с с ускорением.
- Сид забега — `crypto.getRandomValues`, хранится в `lastRun.seed`. Мир: платформы 64×14 px, пул объектов, без аллокаций в горячем цикле.
- Пороги: 0–1500 px — только статичные; 1500+ — движущиеся (доля растёт до 40%); 4000+ — исчезающие (исчезают после одного отскока; доля до 30%); зазоры растут от 70 до 170 px; пружины с 800 px; ракеты с 2000 px, не чаще 1 на 2500 px.
- Фон: градиент от интерьера комнаты к ночному небу со звёздами по мере высоты, параллакс пиксельных облаков/зданий.
- Отрисовка: `requestAnimationFrame`, интерполяция по `alpha`; спрайты — предрисованные offscreen-canvas.

### §8. Экранный поток

```
загрузка (≤1.5 с ожидания AUTH_INIT во встраивании) →
  isCompleted?  да → arcade (профиль + «Играть») ↔ leaderboard
                нет → [G03 restore?] → quest: intro → room1..4 → triumph → arcade
```
`navigation.currentScreen` отражает экран; охрана маршрутов — в одном месте (роутер). Кнопки «назад» в квест после завершения не существует.

### §9. Вёрстка квеста

Сцена 1600×900: слой картинки (object-fit cover под 16:9) внутри «камеры» (`transform: translate/scale`, переход 1 с `ease-in-out`). Зоны камеры в координатах сцены (стартовые, уточняются по скриншоту в тикете): К1 стол+окно ≈ центр (470, 270); К2 шкаф справа сверху ≈ (1300, 320) + пиксельный робот и электроника (inline SVG) у шкафа; К3 круглый стол с книгой + стеллаж справа снизу ≈ (1200, 690); К4 диван/ТВ + котик ≈ (560, 540) + пиксельные колонки аудиосистемы (inline SVG). Масштаб камеры ≈ 1.6. Hotspot — абсолютная `<button class="ezq-hotspot">` над объектом с пульсирующим контуром и подписью. HUD поверх сцены в стиле кнопок референса (деревянная рамка, скругление): слева меню (звук, «как играть»), справа — счётчик монет, прогресс комнат 1–4.

### §10. Тема

`theme` из AUTH_INIT меняет только панели UI (светлые/тёмные подложки); сцена и аркада неизменны. По умолчанию — тёмная (как фон референса).

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R06 — Web Component | бриф: «через изолированный `iframe` (или Web Component)» — выбран iframe (изоляция полная, стенд под него); Web Component — следующий заход |
| R59 — деплой | размещение на хостинге — внешнее действие, делает пользователь; `dist/` готов к любой подпапке, инструкция в README |
| G03 для гостей между устройствами | без ID платформы ученика не узнать; для гостей — пометка «возможный дубль» у куратора (история 43) |
| Шрифт TT Norms в бандле | коммерческий шрифт — файлы не переданы; подключается стеком `font-family`, если установлен |
| Фоновая музыка | пользователь выбрал «8-бит эффекты» без музыки |
