# 0006. Google-таблицу куратора заполняет триггер базы, а не клиент

## Контекст

Бриф даёт куратору два формата: Google-таблицу через вебхук и Apps Script и страницу `verify.html`. Записи о прохождении попадают в Supabase (см. 0001).

## Решение

Единственный источник правды — `quest_completions`. Триггер `AFTER INSERT OR UPDATE OF is_awarded` вызывает `net.http_post` (pg_net) на `sheets_webhook_url` из `ezq_settings` и передаёт общий секрет `sheets_webhook_secret`. Apps Script сверяет секрет со своими Script Properties и по событию `insert` добавляет строку, а по `awarded` меняет «Статус». Триггер создаётся, только если в базе есть pg_net.

## Почему

- **Клиент сам шлёт вебхук** — отвергнуто: URL и секрет Apps Script оказались бы в бандле, и кто угодно смог бы добавить в таблицу поддельные строки. Кроме того, понадобилась бы вторая офлайн-очередь.
- **Google-таблица как единственное хранилище** отвергнута: в ней нет UNIQUE по коду, нет доступа по правилам, нельзя восстановить прохождение по `student_id` (G03), и она не годится как бэкенд для `verify.html`.
- **Apps Script по расписанию забирает данные из Supabase** — отвергнуто: в Apps Script пришлось бы хранить сервисный ключ, строки появлялись бы с задержкой вместо «в реальном времени», а удалённых частей стало бы больше.
- **Посредник на Edge Function** отвергнут: это ещё один сервис для деплоя.

## Последствия

- Таблица — производная копия. Правки в ней не попадают в базу, поэтому «начислено» нужно отмечать в `verify.html`, иначе данные разойдутся.
- pg_net работает асинхронно и не повторяет запросы. Если Apps Script недоступен, строка теряется молча, и сверять приходится по `verify.html`.
- Без pg_net (в том числе в тестах на PGlite) Google-таблицы нет совсем, остаётся только `verify.html`.
- Секрет вебхука хранится в базе в `ezq_settings`, закрытой RLS, и в Script Properties. Менять его нужно в обоих местах сразу.
