# 0002. Рейтинг — сумма засчитанных очков за сезон, `leaderboard` становится представлением

## Контекст

В §4.2 CLAUDE.md `leaderboard` задуман как одна строка на забег (`session_id UNIQUE`, `score ≤ 50000`). На брифинге пользователь выбрал другое: сумму очков всех забегов (G01), сезоны с итогами, которые подводит куратор (G02), дневной лимит 3000 (G05, G09) и скрытие ников (G04). Момент «итогов» для ТОП-3 в брифе не определён.

## Решение

Сумма ученика хранится в `leaderboard_entries`: одна строка на пару «сезон × код», `score` — сумма засчитанного, есть `is_hidden`. Каждый забег пишется в журнал `arcade_runs`: `run_id UNIQUE`, туда переезжают CHECK-и из §4.2, плюс `counted_score` и `day_msk`. Кроме того, есть `seasons` (всегда ровно один активный), `season_winners` и `ezq_settings`. `leaderboard` — это представление текущего сезона без скрытых строк, кодов и `student_id`, поэтому URL из брифа работает буквально. Сутки для лимита считаются по Москве. Сезон закрывает только куратор.

## Почему

- **Таблица §4.2 без изменений** отвергнута. `UNIQUE session_id` и потолок 50000 несовместимы с накопленной суммой. Одна строка на забег даёт ТОП-10, забитый одним учеником, а сумму пришлось бы агрегировать при каждом чтении.
- **Лучший забег на ученика** отвергнут пользователем: нужен повод возвращаться каждый день.
- **Сумма без дневного лимита** отвергнута: побеждал бы тот, у кого больше свободного времени, а не тот, кто лучше играет.
- **Вечный рейтинг без сезонов** отвергнут. Через месяц новичкам в нём уже не пробиться, а у фразы «ТОП-3 на момент подведения итогов» нет момента.
- **Сумма, которую считает само представление из `arcade_runs`,** отвергнута: каждое чтение (раз в 20 с у каждого открытого экрана) означало бы полную агрегацию. Хранимая сумма обновляется апсертом в `submit_arcade_score`.

## Последствия

- В этой части схема расходится с §4.2 CLAUDE.md, и CLAUDE.md её больше не описывает.
- Одни и те же данные лежат в двух местах: сумма в `leaderboard_entries` и журнал в `arcade_runs`. Менять их можно только в одной транзакции RPC.
- Итоги подводятся вручную. Если куратор не нажмёт «Подвести итоги», то после `ends_at` забеги перестают засчитываться, а ТОП-3 не архивируется.
- «Очки забега» и «очки в рейтинг» теперь разные числа. Интерфейс обязан показывать оба, иначе дети решат, что их обманули.
