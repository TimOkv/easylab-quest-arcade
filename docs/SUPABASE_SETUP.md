# Настройка базы Supabase — пошагово

Эта инструкция для человека без опыта программирования. Займёт около 20 минут.
После неё квест начнёт сохранять прохождения в базу, заработает рейтинг аркады,
а у куратора появится кабинет `verify.html` для проверки кодов учеников.

Без базы сайт тоже работает — в **демо-режиме**: квест проходится, код выдаётся,
аркада играется, но в реестр куратора и в общий рейтинг ничего не попадает.

Что понадобится:

- почта для регистрации в Supabase (бесплатного тарифа хватает);
- файл `supabase/schema.sql` из этого проекта;
- доступ к папке проекта, чтобы создать в ней файл `.env` (или человек, который собирает сайт).

> **Про секреты.** В этой инструкции вместо настоящих значений стоят заглушки вида
> `<ваш-секрет-куратора>`. Настоящие секреты никуда не вставляйте, кроме указанных мест,
> и не присылайте их в чаты.

---

## Шаг 1. Создать проект

1. Откройте [supabase.com](https://supabase.com) и нажмите **Start your project** → войдите (удобнее всего через GitHub или почту).
2. Нажмите **New project**.
3. Заполните:
   - **Name** — например, `easylab-quest`;
   - **Database Password** — нажмите **Generate a password** и сохраните пароль в надёжное место (он понадобится только в экстренных случаях);
   - **Region** — ближайший к ученикам, например **Central EU (Frankfurt)**.
4. Нажмите **Create new project** и подождите 1–2 минуты, пока проект создаётся.

## Шаг 2. Создать таблицы и функции (один SQL-файл)

1. В левом меню проекта откройте **SQL Editor**.
2. Нажмите **New query** (или «+»).
3. Откройте файл `supabase/schema.sql` из проекта в любом текстовом редакторе, выделите **всё** (`Ctrl+A` / `Cmd+A`), скопируйте и вставьте в окно запроса.
4. Нажмите **Run** (или `Ctrl+Enter`).
5. Внизу должно появиться **Success. No rows returned**. Сообщения-уведомления (notice) — это нормально.

Файл можно запускать повторно (например, после обновления проекта) — ничего не сломается
и данные не удалятся.

## Шаг 3. Придумать секрет куратора

Секрет — это пароль от кабинета куратора `verify.html`. Минимум 8 символов,
лучше 16+ и без пробелов (например, три случайных слова через дефис и цифры).

1. В **SQL Editor** откройте новый запрос (**New query**).
2. Вставьте строку, заменив заглушку своим секретом (кавычки оставьте):

   ```sql
   select public.ezq_set_curator_secret('<ваш-секрет-куратора>');
   ```

3. Нажмите **Run**. Готово: база хранит не сам секрет, а его отпечаток (хэш).

Секрет можно сменить в любой момент, повторив этот шаг, — старая ссылка куратора
сразу перестанет работать.

## Шаг 4. Взять адрес проекта и публичный ключ

1. В левом меню внизу нажмите **Project Settings** (значок шестерёнки).
2. Откройте раздел **API** (в новых версиях панели — **Data API** для адреса и **API Keys** для ключей).
3. Скопируйте:
   - **Project URL** — адрес вида `https://<ваш-проект>.supabase.co`;
   - публичный ключ **anon public** — длинная строка, начинается с `eyJ…`.
     Если в панели есть вкладки, он лежит на вкладке **Legacy API Keys** (ключ `anon`).

> ⚠️ Нужен именно **anon / public**. Ключ **service_role** (или **secret**) давать
> сайту нельзя никогда — он открывает базу целиком.

Публичный ключ не секретный: он всё равно виден в браузере любому посетителю.
Защита держится на правилах базы (RLS) — это уже сделал `schema.sql`.

## Шаг 5. Прописать адрес и ключ в сайт (`.env`)

1. В корне проекта лежит файл `.env.example`. Сделайте его копию с именем `.env`.
2. Откройте `.env` и заполните две строки:

   ```
   VITE_SUPABASE_URL=https://<ваш-проект>.supabase.co
   VITE_SUPABASE_ANON_KEY=<ваш-anon-ключ>
   ```

3. Пересоберите сайт: `npm run build` (или попросите того, кто выкладывает сайт).
   Значения «вшиваются» в сборку — без пересборки сайт их не увидит.
4. Файл `.env` не выкладывайте в открытый доступ и не отправляйте в git — он уже в списке исключений.

## Шаг 6. Кабинет куратора

Откройте на выложенном сайте ссылку:

```
https://<адрес-сайта>/verify.html#k=<ваш-секрет-куратора>
```

- Секрет стоит после `#` — такая часть ссылки **не уходит на сервер сайта** и не попадает в его журналы.
- Сохраните ссылку в закладки браузера и никому не пересылайте: кто знает секрет, тот может отмечать начисления.
- Если открыть `verify.html` без секрета или с неверным — страница попросит ввести секрет.
- Кнопка **Выйти** стирает секрет из адресной строки.

Что умеет кабинет:

| Вкладка | Что делать |
|---|---|
| **Проверка кодов** | Ввести код ученика (`EZ-8492`, `ez8492` — не важно) → карточка: сколько EasyCoins начислить, имя, ID, дата (МСК). Кнопка «Отметить коины как начисленные». Ниже — последние 50 прохождений, обновляются сами каждые 15 секунд. Пометка «возможный дубль» — есть другое прохождение с тем же именем или ID. |
| **Рейтинг и сезон** | Название сезона и дата итогов (ученики видят таймер), дневной лимит очков (100–100 000), полный рейтинг с кодами, «Скрыть из рейтинга» для неприличных ников, «Подвести итоги и начать новый сезон», прошлые победители. |

## Шаг 7 (необязательно). Google-таблица с прохождениями

База может сама дописывать каждое прохождение в Google-таблицу школы.

1. Сначала выполните инструкцию [`docs/GOOGLE_SHEETS.md`](GOOGLE_SHEETS.md) — в конце у вас будут
   **адрес веб-приложения** (`https://script.google.com/macros/s/…/exec`) и **секрет таблицы**.
2. Проверьте, что в базе включено расширение **pg_net** (через него база отправляет данные):
   **Database** → **Extensions** → в поиске `pg_net` → переключатель должен быть включён.
   Если он выключен — включите и **ещё раз выполните `schema.sql`** (шаг 2), чтобы создались триггеры.
3. В **SQL Editor** выполните, подставив свои значения:

   ```sql
   update public.ezq_settings
      set sheets_webhook_url    = '<адрес-веб-приложения>',
          sheets_webhook_secret = '<ваш-секрет-таблицы>'
    where id = 1;
   ```

4. Проверка: пройдите квест на сайте (или попросите ученика). Через несколько секунд в таблице
   появится строка. Нажмите в кабинете «Отметить коины как начисленные» — «Статус» в строке
   сменится на «Начислено».

Отключить таблицу: выполните тот же запрос с `null` вместо адреса.

## Если что-то не работает

| Что видно | Что сделать |
|---|---|
| В кабинете: «Сервер не настроен» | Не заполнен `.env` или сайт не пересобран (шаг 5). |
| В кабинете: «Секрет не подошёл» | Проверьте секрет в ссылке; при необходимости задайте новый (шаг 3). |
| В кабинете: «Нет связи с сервером» | Проверьте интернет. Если проект Supabase долго не использовался, бесплатный тариф ставит его на паузу — откройте проект в панели и нажмите **Restore**. |
| Ученик видит «Отправим куратору, как только появится интернет» | Сайт повторит отправку сам. Если так надолго — проверьте шаги 4–5. |
| Строки не появляются в Google-таблице | Проверьте шаг 7: включён ли `pg_net`, совпадает ли секрет в Apps Script и в базе, развёрнута ли **новая версия** веб-приложения с доступом «Все». Сайт и кабинет от таблицы не зависят — все данные всё равно есть в кабинете. |
| Ошибка при запуске `schema.sql` | Убедитесь, что скопирован **весь** файл целиком, и запустите ещё раз. |
